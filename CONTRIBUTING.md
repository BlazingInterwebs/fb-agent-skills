# Contributing

Bring a specific workflow improvement, observable bug, or current primary
source. Don't grow the inventory by splitting every post intention into a skill.

1. Open an issue describing the user problem, relevant surface, expected behavior,
   available evidence, and privacy constraints. Redact real users and secrets.
2. Make a scoped change. Keep name/description discovery precise and instructions
   outcome-focused. Put substantial mode-specific detail in linked references.
3. Edit canonical common references/helpers under `shared/`, then run
   `python3 -B scripts/sync_resources.py`. Don't edit generated shared copies alone.
4. Add deterministic tests for scripts and realistic behavioral cases for
   methodology. Don't claim a wording-matching test proves creative quality.
5. Run validation and tests from README. Check a standalone copied skill as
   well as the complete collection. Preserve runtime fallback and no-overwrite
   installation behavior.
6. Document evidence scope/date and limitations. Keep official guidance,
   observation and hypothesis distinct. Add a changelog entry for user-facing changes.

## Contribution boundaries

No private exports, brand files, client stories, personal identifiers, tokens,
or copyrighted media. No invented APIs, guaranteed ranking signals, universal
AI-detector claims, destructive Unicode cleaning, or growth promises. New
integrations need separate authorization, data-handling review, current official
capability checks and tests. Do not bypass the free export-based workflows.

Submitting a contribution proposes its inclusion under this project's MIT
license. Identify third-party licenses explicitly; maintainers must review
compatibility and required notices before merging.
