# Facebook planning

Read [runtime](references/runtime.md), [growth](references/growth.md), and
[surfaces](references/surfaces.md). Use [privacy](references/privacy.md) for
source reuse and [planning](references/planning.md) to build a usable calendar.

## Plan from constraints

Use goals, intended audience, surface(s), actual available time/production
capacity, approved assets, offer relevance, and past evidence. A growth goal
needs an editorial promise and a reason to return, not just more posts.
If analytics are absent, create a labeled starting hypothesis; don't fabricate
an optimal schedule or claim a universal best posting time.

Balance discovery, useful depth, relationship, and appropriate business content
based on the objective. Avoid fixed platform-wide ratios. Select coherent
themes/series without repeating identical openings. Allocate reuse across
formats only where it creates standalone value. Respect group-specific rules;
don't list Groups as places to paste the same promotion.

Reserve enough capacity for thoughtful replies when relevant, without claiming
a compulsory engagement ritual causes reach. Plan a manageable number of
experiments with clear metrics and windows. Record what would change the next
plan; keep tentative creative ideas distinct from committed publication.

## Deliver and route

Return calendar with surface, audience, objective, angle, format, needed assets,
owner/status, proposed time/timezone if relevant, optional CTA, and success
measure. Explain assumptions and production bottlenecks. Include an experiment
card and a fallback when an asset cannot be made. Route selected briefs to
format skills; use `fb-audit` results to revise the plan. Don't silently draft
all assets, schedule anything, or promise platform growth from cadence alone.
