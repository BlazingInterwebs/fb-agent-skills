# Runtime and task boundaries

This collection is independently authored, user-neutral, and draft-only.
It does not contain an API, connector, browser, account authorization,
publishing integration, image renderer, or video editor. Use only capabilities
actually exposed in the current host. Never pretend a tool or sibling skill ran.

## Intake

Use supplied information first. Establish the intended surface (ordinary
profile, professional-mode profile, Page, or Group), audience/visibility,
objective, deliverable, and verified source material. Ask only for missing
information that materially changes the task. A reasonable assumption may
support a provisional draft, but label it. Never invent facts to finish intake.
Read private context only when the user has authorized its use for this task.
No global voice, CRM, meeting, or personal-memory file is assumed.

## Execution

- Read this reference when first using a skill in a conversation. Read the
  other references linked by that skill only when their mode applies.
- Execute a helper by its resolved absolute path, not an assumed working
  directory. Python helpers need Python 3.9+ and the standard library only.
  If execution is unavailable, give a labeled manual calculation/review,
  or request the missing data. Never fabricate a helper receipt.
- Browse only if browsing exists and research is requested or needed. When
  pages are blocked, use user-supplied material or accessible primary sources.
  Do not bypass access controls, collect credentials, or set up a crawler.
- Handoffs mean reading the available specialist's instructions and applying
  them to the requested work. They do not create chats or autonomous workers.
  If a sibling is absent, use the selected skill's own reference for a scoped
  fallback; say which specialist was unavailable when that matters.
- Match output volume to the request. A single post does not require a full
  calendar, audit, engagement campaign, or unsolicited research.
- Writing files is optional and requires the user's task to authorize it.
  Prefer inline drafts; otherwise use a user-selected workspace. Never store
  private data inside installed skill folders or this public source tree.

## Handoff contract

Pass only relevant context: objective; surface and visibility; intended reader;
voice excerpts/preferences; approved factual claims and source locations;
rights/privacy constraints; selected angle; requested format; CTA if useful;
available assets; success metric; evidence confidence; unresolved questions.
Do not pass whole private conversations when a redacted summary is sufficient.
The receiving skill owns its composition, not the researcher's wording.

## Authority

User facts and preferences govern voice and objectives. Current official
platform restrictions govern technical availability. Group rules govern
community participation. Actual comparable performance outranks creative
heuristics. A high editorial assessment never overrides safety or evidence.

`fb-research` owns external evidence; `fb-audit` owns measured learning;
`fb-repurpose` owns extraction; `fb-plan` owns allocation; format skills own
composition; `fb-human` owns voice revision; `fb-group` owns group constraints.
Drafts are not published, scheduled, sent, or approved by these skills.
